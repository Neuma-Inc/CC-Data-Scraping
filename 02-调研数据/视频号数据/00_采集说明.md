# 视频号数据采集 · 采集说明（B 模式：人工点开 + 机器读取）

更新时间：2026-11-04
环境：微信 4.2.0.13（Weixin.exe），屏幕 2560×1600 @150% DPI
方式：人工在微信里搜索并点开视频，程序只读窗口内容，不注入任何点击/按键。

## 一、分工

**人做**：搜索关键词 → 切到「视频」tab → 点开第 N 条 → 听到提示音后关掉播放窗 → 点开下一条。
**机器做**：发现播放窗 → UIA 读取字段 → 截屏 → 追加 CSV → 响提示音。

## 二、启动

```
cd "D:\A-灵知生物\小程序\05-市场调研\03-抓取工具\wechat-video-capture"
.venv\Scripts\python.exe collector.py
```

停止：Ctrl+C。
测试运行（不采集，只验证循环）：`collector.py --test-seconds 8`。

## 三、提示音约定

| 声音 | 含义 |
|---|---|
| 1 声（1100Hz，0.2 秒） | 已记录，可以关掉这条、打开下一条 |
| 2 声（700Hz，各 0.13 秒，间隔 0.12 秒） | 这条已存在，未重复记录 |

## 四、输出文件

| 文件 | 说明 |
|---|---|
| `视频号_内容明细.csv` | UTF-8-SIG，逐条追加，每行写完立即 flush |
| `截图\{关键词}_{序号}.png` | 播放窗整窗截屏 |
| `当前关键词.txt` | 采集器据此给新行打关键词；换词时改这个文件 |
| `采集日志.log` | 运行日志，含每条记录与进度 |

## 五、CSV 字段与取值口径

| 列 | 来源 | 口径 |
|---|---|---|
| 关键词 | `当前关键词.txt` | 切换关键词时改该文件 |
| 序号 | 该关键词下自增 | 只对「新记录」自增，重复条不占号 |
| 标题 | 播放页简介去掉 #话题 后的正文 | 视频号没有独立标题，标题与简介同源 |
| 作者 | 播放页作者名 | 原样 |
| 点赞数 | 播放页「喜欢」 | 这是列表卡上公开展示的那个数，与其他平台口径可比 |
| 评论数 | 播放页「评论」 | 原样 |
| 收藏/转发 | 播放页「分享」 | 视频号无独立收藏数，此处填分享数 |
| 相对发布时间 | 播放页 UIA（找不到则留空） | 只记相对时间，如「2个月前」，不做绝对日期换算 |
| 时长(如有) | 播放页进度条 | 视频未加载出时长时留空 |
| 简介/话题 | 播放页原文 | 含 #话题，原样保留 |
| 截图文件名 | 自动 | `关键词_序号.png` |
| 采集时间 | 本机时间 | `YYYY-MM-DD HH:MM:SS` |
| 推荐数(点赞按钮) | 播放页「点赞」（👍） | 视频号的「推荐」，与「喜欢」是两个不同指标，单列保留 |

说明：视频号的「喜欢」和「点赞」是两个独立按钮，数值也不同（例：喜欢 6144 / 点赞 858）。为避免与其他平台混口径，CSV 的「点赞数」取「喜欢」，「推荐数(点赞按钮)」单独保留。

## 六、去重与断点续采

- 去重 key：`标题 + 作者`（标题取播放页简介原文）。
- 程序启动时读取已有 CSV 建立 key 集合；再次打开同一条会响两声、不写入。
- 中途停止后重跑会自动续采，序号接着已有记录继续。

## 七、已知限制

1. **相对发布时间不一定拿得到**。播放页通常不展示，程序会先扫 UIA 树里的「N分钟/小时/天/周/个月/年前」「刚刚/今天/昨天/前天」；扫不到就截一张主窗结果列表存到 `截图\_待补时间\{关键词}_{序号}.png`，事后人工核对该卡片上的相对时间补进 CSV；再没有就留空，不猜。
2. 时长依赖视频加载，未加载时留空。
3. 无收藏数（平台不提供）、无播放量（列表不提供）。
4. 相对时间无法换算成绝对日期（「2个月前」按采集日倒推会有误差），按原样保留。
5. 播放窗内下滑是推荐流而非搜索结果，因此必须由人按顺序点开搜索结果中的第 N 条，程序只读当前窗口。
