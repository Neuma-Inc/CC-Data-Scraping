## 一、调研背景与核心目标

### 1.1 四大商业目的
本次数据调研服务于灵知生物「减重相关课程」从 0 到 1 的设计决策，需用真实平台数据回答以下四个问题：
1. **给课程设计提供数据支持与方向**：目前课程形态未定，需通过数据看清免费内容已经讲透了什么（不重复造轮子）、用户真正卡在哪一步（课程该交付什么机制）。
2. **确认目标用户（锚定高付费意愿人群）**：对全量减重人群进行无偏采样，通过可量化的「付费意愿代理信号」（指标异常、失败成本、决策紧迫度）排出优先级，识别最愿意为减重服务买单的人群画像。
3. **确认核心痛点与需求边界**：不仅要抓用户「想要什么」，更要抓用户在执行中「卡在哪里」以及「明确不要什么」（如不要挨饿、不要复杂备菜、不要每天机械打卡）。
4. **摸清市面服务水位并找到灵知差异化**：在不做竞品买课拆解的前提下，从公开内容与真实用户评论中摸清市面减重训练营、线上营养师、陪跑群、代餐及减重药物的「承诺—交付—塌房区」，结合灵知自有优势（专业营养师团队、体检报告解读、拍照饮食诊断、全家定制食谱、健康豆激励体系、功能营养品矩阵）找到差异化切口。

### 1.2 三条铁律（抓取基本原则）
1. **三平台全量对齐，不缩水、不偏科**：小红书、抖音、B站三个平台全部跑满同一套关键词包与完整字段，不做配额阉割，确保每个细分维度都能做三平台横向对比。
2. **锁死近 3～6 个月时效，剔除陈旧噪音**：减重赛道风向迭代极快（早期流行哥本哈根、代餐粉，近半年转向控糖、抗炎饮食、16+8、生活化减脂、GLP-1/司美格鲁肽反弹管理等）。**早于 2026-05-03 的内容一律在抓取层直接拦截丢弃**，不拉详情、不抓评论、不占配额。
3. **严格区分「供给侧（博主发什么）」与「需求侧（用户卡在哪）」**：爆款视频和图文代表的是创作者供给与算法偏好；真正的需求藏在**高赞共鸣评论、楼中楼追问、以及素人自己发布的求助帖与踩坑帖**中。

## 三、需求侧调研模型：抓回来的数据要回答什么？

为避免把「看热闹的爆款」当成「真需求」，第一阶段数据抓取围绕 **五层需求结构** 与 **七个量化指标** 展开：

### 3.1 用户需求五层拆解框架

| 层级 | 核心问题 | 具体分层 / 拆解维度 | 对课程与产品设计的意义 |
|---|---|---|---|
| **第 1 层：认知阶梯** | 用户卡在解决问题的哪一步？ | **L0** 未意识 $\rightarrow$ **L1** 感知症状（累/肚子大/水肿） $\rightarrow$ **L2** 寻找归因（代谢慢/胰岛素抵抗/湿气） $\rightarrow$ **L3** 比较方案（16+8/低碳/抗炎） $\rightarrow$ **L4** 执行卡住（外食/没空做饭/暴食） $\rightarrow$ **L5** 维持失败（平台期/反复反弹） | L1–L3 免费科普已极度饱和；**课程要想收费，必须锚定在免费内容解决不了的 L4（执行机制）与 L5（防反弹与卡点突破）**。 |
| **第 2 层：触发场景** | 什么事件让他此刻立刻想花钱？ | **强触发**：体检报告异常、医生警告、备孕/产后/更年期身体信号<br>**中触发**：婚礼/同学会/换季穿不下衣服、同龄人对比<br>**弱触发**：算法偶遇刷到视频 | 决定获客钩子（Hook）怎么写、什么季节/节点推什么主题（如春秋季体检高发期主推指标调理减重）。 |
| **第 3 层：任务结构（JTBD）** | 他真正想完成的进展是什么？ | **功能任务**：降指标、减尺码、学会点外卖/配三餐、不挨饿<br>**情感任务**：吃饱不自责、摆脱失控感、不被说教评判<br>**社会任务**：体面、照顾全家饮食同时自己瘦 | 决定课程的服务态度、交付颗粒度与社群氛围设计。 |
| **第 4 层：替代方案** | 在买课之前他在用什么解法？ | 自搜免费菜谱、硬饿/跳餐、代餐粉/黑咖啡、减肥针（司美格鲁肽）、打卡App、健身私教、医院门诊、**直接放弃** | 摸清每种替代方案的「失败率」与「副作用」，把课程定位为替代方案失败后的最优解。 |
| **第 5 层：需求边界（排除项）** | 用户明确拒绝什么？ | 不要挨饿、不要买昂贵罕见食材、不要复杂烹饪、不要和家人分开做两锅饭、不要每天机械打卡、不要推销式卖货 | **排除项是课程设计的硬红线**，踩中任何一条都会直接拉低完课率与转化率。 |

### 3.2 七个可计算量化指标

1. **收藏点赞比（$\text{Collected} \div \text{Liked}$）**：衡量内容的「工具/干货属性」（越接近或超过 100%，说明用户越倾向于存下来照着做，而非纯娱乐消费）。
2. **评论追问比（$\text{Sub\_Comments} \div \text{Top\_Comments}$）**：衡量话题的「实操争议度与痛点共鸣度」。
3. **求索密度**：评论中含「求、怎么、能不能、替代、外食、多少克」等实操求助词的占比，反映现有免费内容未讲清的缺口。
4. **指标与疾病词密度（高付费意愿核心代理指标）**：评论或正文中主动提及具体数值（体重基数、BMI、血糖、糖化、尿酸、血脂）或医学诊断（胰岛素抵抗、脂肪肝、多囊、甲减）的占比。**肯在评论区报出自己具体指标的人，转化率远高于只喊「求食谱」的围观者。**
5. **失败与反弹密度（L4/L5 代理指标）**：提及「反弹、复胖、平台期、坚持不住、暴食、试过没用」的占比。
6. **竞品抱怨分布**：在训练营/营养师/陪跑相关内容下，提及「模板化、没人管、推销产品、太贵、停了就胖」的分类频次。
7. **近 3 个月热度增速**：近 3 个月（2026.08–11）内容量与互动量相对于前 3 个月（2026.05–08）的占比变化，识别最新上升趋势。

### 4.1 双通道采样设计
- **通道 A（近半年爆款供给 + 万人高赞共鸣）**：
  - 适用平台：小红书、抖音、B站三端全开。
  - 排序方式：小红书 `popularity_descending`（最热）、抖音综合高赞（带半年内筛选）、B站综合排序（带近半年时间戳筛选）。

- **通道 B（近 3～6 个月素人真实求助 + 报课踩坑帖）**：
  - 适用平台：小红书（用户把小红书当论坛和避坑搜索引擎用）。
  - 排序方式：针对词包 1、2、3 加跑一轮 `general`（综合）与 `time_descending`（最新）。

## 六、落盘数据字段与目录规范

### 6.1 落盘文件路径
- **小红书**：`01-开发/数据抓取工具/MediaCrawler/data/xhs/jsonl/`
- **抖音**：`01-开发/数据抓取工具/MediaCrawler/data/douyin/jsonl/`（注意目录名为 `douyin`）
- **B站**：`01-开发/数据抓取工具/MediaCrawler/data/bili/jsonl/`

### 6.2 核心采集字段清单
- **内容表（`search_contents_*.jsonl`）**：
  - 唯一标识与来源：`note_id` / `aweme_id` / `video_id`、`source_keyword`（命中的搜索词）、内容 URL
  - 文本与标签：`title`（标题）、`desc`（正文/简介）、`tag_list`（话题标签）、`type` / `aweme_type`（图文或视频）
  - 发布时间：`time` / `create_time`（精确到秒/毫秒，用于划分「近 3 个月」与「3～6 个月」）
  - 互动全指标：`liked_count`（点赞）、`collected_count` / `video_favorite_count`（收藏）、`comment_count` / `video_comment`（评论）、`share_count` / `video_share_count`（分享）、`video_play_count`（B站播放）、`video_coin_count`（B站投币）、`video_danmaku`（B站弹幕）
  - 创作者信息：`nickname`、`creator_hash` / `user_id`
- **评论表（`search_comments_*.jsonl`）**：
  - 关联关系：`comment_id`、`note_id` / `aweme_id` / `video_id`、`parent_comment_id`（`0` 或空串代表一级评论，非零代表二级楼中楼回复）
  - 评论内容与时间：`content`（评论原话）、`pictures`（评论带图，如晒餐盘、晒体检单）、`create_time`
  - 权重指标：`like_count`（评论点赞数，用于识别高共鸣痛点）、`sub_comment_count`（楼中楼追问数，用于识别高争议/高关注问题）

## 七、分批执行流程与操作命令

### 7.1 四批次执行顺序
为保障账号安全、及时处理可能出现的平台滑块验证，并确保每跑完一批就能实时落盘校验，按以下 4 个批次依次执行：

1. **第一批（Batch 1）**：运行 `pack1_high_pay`（高付费意愿人群，9 词 × 三平台）
2. **第二批（Batch 2）**：运行 `pack2_pain_points`（L4/L5 执行卡点，9 词 × 三平台）
3. **第三批（Batch 3）**：运行 `pack3_competitors`（竞品水位与差评，8 词 × 三平台）+ `pack4_benchmarks`（主流方案基准，5 词 × 三平台）
4. **第四批（Batch 4，小红书素人求助与避坑补采）**：针对词包 1、2、3，将小红书排序切换为 `general` / `time_descending` 补采一轮素人近期发帖，并对评论区讨论最激烈的 Top 15「神帖」用 `detail` 模式全量深扒评论。

### 7.2 自动化执行命令（PowerShell）

在 `01-开发/数据抓取工具/MediaCrawler` 目录下，直接调用已编写好的分批调度脚本 `run_survey_batches.py`（每跑完一个平台会自动调用 `clean_and_audit_recent.py` 执行近半年时效过滤与按 ID 去重）：

```powershell
# 进入 MediaCrawler 目录并开启 UTF-8
$env:PYTHONUTF8='1'
cd "D:\A-灵知生物\小程序\01-开发\数据抓取工具\MediaCrawler"

# 1. 跑第一批：高付费意愿人群（三平台全量）
uv run python run_survey_batches.py --pack pack1_high_pay --platforms bili,xhs,dy --notes 20

# 2. 跑第二批：L4/L5 执行卡点（三平台全量）
uv run python run_survey_batches.py --pack pack2_pain_points --platforms bili,xhs,dy --notes 20

# 3. 跑第三批：市面竞品水位与差评 + 主流方案基准（三平台全量）
uv run python run_survey_batches.py --pack pack3_competitors --platforms bili,xhs,dy --notes 20
uv run python run_survey_batches.py --pack pack4_benchmarks --platforms bili,xhs,dy --notes 20

# 4. 跑第四批：小红书切换 general（综合）/ time_descending（最新）补抓素人真实求助与避坑帖
uv run python run_survey_batches.py --pack pack1_high_pay --platforms xhs --notes 15 --xhs-sort time_descending
uv run python run_survey_batches.py --pack pack2_pain_points --platforms xhs --notes 15 --xhs-sort time_descending
uv run python run_survey_batches.py --pack pack3_competitors --platforms xhs --notes 15 --xhs-sort general
```
